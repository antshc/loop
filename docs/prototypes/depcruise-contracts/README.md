# dependency-cruiser import contracts spike (issue #124)

## Question

Can dependency-cruiser, run inside `bun test` on a TS skeleton of `src/loop` + `workflows/`, express each `pyproject.toml` import-linter contract one-to-one and fail on a seeded violation of each (plus "only `observe/otel.ts` imports `@opentelemetry/*`")?

## Method

`./run.sh` (one command; needs only Bun) runs `bun test` → `contracts.test.ts`, which calls `cruise()` from `dependency-cruiser` 18.7 with the rules in `.dependency-cruiser.cjs`.

- `skeleton/` is generated by `gen_skeleton.py` from the real Python sources: 97 modules (packages → `index.ts`), 275 side-effect `import`s, one per first-party import incl. lazy/`TYPE_CHECKING` ones; `opentelemetry*` → `@opentelemetry/api`. Real code passes `lint-imports` (5 kept), so the clean skeleton is a faithful baseline.
- Each seeded case copies the skeleton to `out/cases/<case>/`, appends 1–2 `import` lines, cruises it, and asserts the expected rule fires from the expected module. Indirect cases route through a module outside the constrained set (`loop/log.ts`, `workflows/index.ts`, `pr_babysit/settings.ts`, `dev/checkout.ts`).
- Contrast case: same layers-indirect fixture with `reachable` stripped from every rule.

Semantics mapped (import-linter defaults): `layers` forbids upward imports *and indirect chains*; `a | b` siblings are mutually independent; `containers` scopes layer names to `loop`; `forbidden` forbids indirect chains unless `allow_indirect_imports = true` (only contract 2); `independence` forbids direct and indirect imports between every pair. No contract uses `ignore_imports`.

## Observation

13/13 tests pass. dependency-cruiser `reachable: true` rules express transitive forbidding; plain rules are direct-only.

| Contract | depcruise rule(s) | One-to-one? | Seeded violation caught? |
|---|---|---|---|
| 1 layers (`containers=["loop"]`) | 7 `layers/<layer>-not-above` + 7 `layers/<name>-independent-of-siblings`, all `reachable: true`, generated from one `LAYERS` array | Semantically yes; 1 contract → 14 rules (no native `layers` type); `containers` = path prefix | Yes: direct, indirect (`observe → log → builder`), sibling (`clis → git`) |
| 2 workflows → public `loop` only (`allow_indirect_imports`) | `workflows-public-loop-only` (direct, no `reachable`) | Yes | Yes; clean baseline (workflows → `loop/index` → private) not flagged, so indirect is allowed |
| 3 `dev.attempt` ↛ `dev.agent/repositories/run` | `dev-attempt-no-agent-workflow`, `reachable: true` | Yes | Yes: direct and indirect (via `checkout`) |
| 4 workflow independence | `workflows-independent`, `reachable: true`, `to.pathNot: "^workflows/$1…"` group match | Yes (one rule, all pairs) | Yes: direct and indirect (via `workflows/index.ts`) |
| 5 `pr_babysit.workflow` ↛ `infrastructure.scheduler` | `pr-babysit-workflow-no-scheduler`, `reachable: true` | Yes | Yes: direct and indirect (via `settings`) |
| Extra: only `observe/otel` imports `@opentelemetry/*` | `otel-only-in-observe-otel` (`from.pathNot` + `to.path`) | n/a (new rule) | Yes (`clis/runner.ts`) |

- Contrast: with `reachable` removed, the indirect layers chain yields 0 violations — `reachable: true` is required to match import-linter's default.
- Finding on real code: the clean skeleton flags `loop/workflow/adapters/otel.py`, which lazily imports `opentelemetry.trace`; the extra rule does not hold today.
- Reporting differs: a `reachable` rule reports one violation per (from-module, reachable target), so one seeded edge fans out (layers cases: 100 violations; `clis → git`: 42; `workflow_reporting → dev`: 20), versus import-linter's one chain per broken pair. Chains aren't printed in the summary.
- Gotchas: dependency-cruiser 18.7 supports `typescript >=2 <7`; `bun add typescript` installed 7.0 (native port), outside that range — pinned `typescript@<7` (6.0.3). Rule objects are schema-validated: `reachable: undefined` is rejected (must delete the key).
- Speed: ~60–140 ms per cruise of 98 modules.

## Conclusion

Yes. Every contract has a faithful dependency-cruiser encoding that runs inside `bun test` and fails on direct and indirect seeded violations. Only `layers` is not one-to-one: it becomes 14 generated rules (upward + sibling-independence); keep the layer list as data in the config and generate rules.

Implications / gaps for the TS port:
- Use `reachable: true` on every rule except the `allow_indirect_imports` one; otherwise transitive chains slip through.
- Pin `typescript` to a range dependency-cruiser supports (`<7` today).
- Expect noisy fan-out reports; assert on rule name, or post-process to one violation per rule/pair.
- `ignore_imports` is unused today; dependency-cruiser has no edge-level exclusion for `reachable` chains (only `from/to.pathNot` on endpoints), so a future chain-breaking exception would need a different encoding — untested.
- Resolve the `workflow/adapters/otel` lazy OTel import (move behind `observe/otel`) before adopting the extra rule.
- Not tested: CLI/`.dependency-cruiser.cjs` auto-discovery, real TS port with tsconfig path aliases or a `loop` package import (skeleton uses relative paths), cycle rules.
