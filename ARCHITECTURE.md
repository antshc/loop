# Loop Overview

Loop is a Python library, installed with `pip` from this repository, for composing autonomous agent Workflows on Git worktrees. It ships no command and no built-in Workflows: the user writes each Workflow as a plain script on the public `loop` API and runs it through their own shell alias. Ralph, the orchestrator, drives the autonomous development loop; Crew agents (Codey, Chorey, Testy) do the work on worktrees from Tickets.

## Goal

Build a headless AI development environment that orchestrates coding agents across Git repositories, manages isolated single-repository and multi-repository harnesses, and supports iterative autonomous development workflows with minimal human intervention.

## Codebase Structure

| Location | Contents |
|----------|----------|
| `loop/src/` | The `loop` library package: `builder.py` and `factory.py` (`Agent()` composition root), and the `agents/`, `clis/`, `git/`, `docker/`, `run/`, `hooks/`, `sessions/`, `observe/`, `dryrun/`, and optional `workflow/` subpackages. |
| `software_factory/` | The software factory at the reporoot, laid out like `loop/`: `src/` (package `software_factory`: `flows/`, `stages/`, `events/`, `runtime/`, `agents/`, `shared/`), `workflows/` (package `factory_workflows`) and `tests/`. Both packages are mapped from this layout by `package-dir`; the factory imports only the public `loop` package ([Keep `software_factory` in this repository as a package root beside `loop`](docs/adr/keep-software-factory-in-this-repository-as-an-unpackaged-root.md)). Layers, top to bottom: `factory_workflows`, `flows/`, `stages/`, `events/`, `runtime/`, then `agents/` and `shared/`. |
| `software_factory/src/agents/` | The typed role agents: one reusable agent per Agent role (developer, planner, chore, reviewer, address, maintainer) that any Workflow runs with a workspace and a typed request and that returns a typed reply or a declined value. Each `roles/<role>/` package holds its messages, profile defaults and prompt resources; the private `_kit/` holds prompt rendering, envelope decoding and agent building. Imports only the public `loop` package, never `shared/` or another role. |
| `software_factory/src/runtime/` | The factory runtime ([Factory Workflow Runtime](docs/concepts/str-factory-workflow-runtime.md)): the declarative definition layer (Stage, Flow and Workflow values validated as they are built, with routes and the four constructs of sequence, per-item loop, exhaustive switch and workspace scope) and the execution layer, `run(...)`, which interprets a definition for one work item through the private `_engine/`: Stage attempts with a trusted gate and a repository contract, routes, an append-only Execution ledger that lets an interrupted run resume, and run, scope and Stage attempt spans. Generic: imports only the public `loop` package and the agents' typed contract, never GitHub, role agents, shared infrastructure or a Workflow, and starts no process itself. |
| `software_factory/src/events/` | The Event vocabulary the Stages produce and read: frozen dataclasses grouped by subject (Specs, Tickets, pull requests, feedback, CI, review, chore, checks) that the Execution ledger serializes. Data only: imports the runtime's Event base and nothing of Git, the GitHub clients or the Stages. |
| `software_factory/src/stages/` | The reusable Stage library: every Stage, Selector and workspace opener, in flat modules by subject (`specs`, `plan`, `tickets`, `publish`, `chore`, `review`, `finalize`, `checks`, `workspaces`, `pull_requests`, `feedback`, `address`, `ci`, `copilot`, `readiness`, `pacing`). Each Stage has complete defaults, and Workflow-specific policy arrives as values or callables, never booleans. Stage modules never import each other, start no process and never reach the private runtime engine or agent kit; the GitHub clients and Git arrive as services. |
| `software_factory/src/flows/` | The reusable Flow fragments: several Stage modules composed once so a Workflow places a whole activity in one statement (today `address.py`, answering a pull request's pending feedback, placed by `pr_babysit` and `address_once`). Holds no Stage logic, starts no process, and exists only while two or more Workflows place a fragment. |
| `software_factory/src/shared/` | Workflow-side infrastructure identical across Workflows: Git, `gh`/GitHub (the repository and account modules, and the `issues/` and `pull_requests/` packages with the Spec and Ticket model, pull request model, clients and pure policies), subprocess, the repository check command, the agent launcher, the pacer, and telemetry (`OtelSpans` exports the runtime's spans over Loop's observer). Imports no Workflow. |
| `software_factory/workflows/implement_spec/` | The `implement_spec` Workflow, runnable with `python -m factory_workflows.implement_spec`: one definition over the Stage library, delivering a Spec's Tickets to a draft pull request, with its policy values (`policy.py`), settings, the intake that selects Specs and releases held work, the entry point that builds the services, and the `--fake`/`--dry` seams. Holds no Stage logic; imports no other Workflow. |
| `software_factory/workflows/pr_babysit/` | The `pr_babysit` Workflow, runnable with `python -m factory_workflows.pr_babysit`: one definition run once per pull request until it closes, addressing feedback, maintaining CI, requesting a Copilot review and reporting readiness, with its policy values, settings, the discovery intake that supervises one child process per pull request, the one-time adoption of the earlier per-PR state into the ledger, and the entry point. Holds no Stage logic; imports no other Workflow. |
| `software_factory/workflows/address_once/` | The `address_once` Workflow, runnable with `python -m factory_workflows.address_once --config cfg.json --pr URL`: addresses the trusted review feedback of one pull request once, assembled only from existing Stages and the shared address fragment, with its policy values, settings and entry point. Holds no Stage logic and no polling; imports no other Workflow. |
| `loop/workflows/` | The standalone public-Loop examples: `workflow_reporting.py` (optional Phase reporting) and the function-based `plan_implement.py`, depending only on the public `loop` API and the standard library. Not part of the `loop` package and not part of the factory. |
| `software_factory/tests/` | The factory test tree, mirroring the source packages (`agents/`, `runtime/`, `events/`, `stages/`, `flows/`, `shared/`, `workflows/<name>/`), plus `architecture/` for the structural rules import-linter cannot express, derived from the code. Fakes sit at the process boundaries (`shared/fakes/` holds the shared `gh` fake). May import any factory package; no factory source package imports it. |
| `loop/tests/` | Library and sibling Workflow tests against fakes, `loop/tests/workflow_harness.py` for the sibling Workflow, and import-linter architecture checks. The root `pytest` command also discovers `software_factory/tests/`. |
| `archive/` | Retired prototypes kept as a parts source only; excluded from search and navigation, never edited or imported. |
| `docs/` | ADRs (`adr/`), Crosscutting Concepts (`concepts/`), building-block records (`building-blocks/`), and research notes. |

| **[Loop Library Workflow Architecture](docs/concepts/str-loop-library-workflow-architecture.md)** | How Workflows are written as user-owned runnable Python on the public `loop` API, with injectable dependencies and settings declared as code. | **Trigger:** new workflow, workflow script, workflow alias, runnable script, __main__ guard, public loop API, loop library, user-supplied workflow directory, built-in workflow, AgentBuilder, Agent(), new_agent, WorkflowGit, IssueClient, PullRequestClient, replace default implementation, custom tracker, dependency injection into workflow, workflow settings as code, hardcoded workflow settings, loop hooks declared in workflow, optional CLI args, config file, loop.toml, workflow independence, example implement_spec workflow, actionable ticket selection, workflow-specific response parser, workflow result model, Clean Architecture, Python package layout, software_factory/src/shared/github, shared GitHub package, Spec and Ticket model in shared, test folder layout, mirror source folders. **Default:** Write each Workflow as user-owned runnable Python (Loop ships none and no command) that imports only the public `loop` API, runs its prompts through an `AgentBuilder` worktree, takes its dependencies as injectable parameters defaulting to the shipped implementations, declares settings and Loop hooks as code with optional CLI overrides and no config file, and owns its response parsing, Git validation, and publication.
