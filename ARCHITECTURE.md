# ralphv2 Overview

A Copilot plugin (`ralph`) of skills for an autonomous development loop and PR review handling, backed by a Python tooling package (`brain-tools`) that exposes the `afk_dev`, `afk_fix_prs`, and `afk_address_prs` CLIs.

## Goal

Build a headless AI development environment that orchestrates coding agents across Git repositories, manages isolated single-repository and multi-repository harnesses, and supports iterative autonomous development workflows with minimal human intervention.

## Architecture Decision Records

An ADR records a point-in-time, localized decision — hard to reverse, surprising without context, and the result of a real trade-off.

| # | Decision | Trigger condition | Summary |
|---|----------|-------------------|---------|
| [0001](docs/adr/0001-install-shipyard-with-pip-from-the-repository.md) | Install Shipyard with pip from the repository | install Shipyard, pip install, brain-tools packaging, distribution channel, PyPI, pipx, zipapp, standalone binary, versioning, delivery to users, running scripts without install, afk_dev entry points | Install `brain-tools` with `pip` from this repository so the repository revision defines the delivered version; no package index, binary, `pipx`, or zipapp distribution. |
| [0002](docs/adr/0002-ship-shipyard-as-the-shipyard-package-with-a-ship-command.md) | Ship Shipyard as the `shipyard` package with a single `ship` command | package name, import path, console script, CLI entry point, command name, ship dev, ship review, afk_dev rename, ralph dev, pyproject project name, subcommand per workflow | The Python package is `shipyard`; it exposes one `ship` console command whose subcommands are the discovered workflows (e.g. `ship dev`). |
| [0003](docs/adr/0003-expose-only-the-runtime-to-user-supplied-workflows.md) | Expose only the runtime to user-supplied workflows | user-supplied workflow, external workflow directory, workflow plugin loading, public API, shipyard.runtime, shared adapters, adapter override, built-in workflows, compatibility surface, third-party workflow imports | Built-in workflows ship in the package and may use shared adapters; workflows loaded from user-supplied directories may import only `shipyard.runtime` and bring their own adapters. |
| [0004](docs/adr/0004-run-only-pre-agent-shell-command-hooks-on-the-host.md) | Run only pre-agent shell-command hooks on the host and fail the run on error | hook, hook point, worktree-ready, pre-agent setup, post-agent hook, sandbox hook, host hook, hook timeout, hook failure, hook callback, setup command, copy .env, install dependencies, Sandcastle hooks | Shipyard supports user-declared shell-command hooks at a `worktree-ready` Hook point, run on the host before the agent; a non-zero exit or timeout fails the run, and there are no post-agent, sandbox-side, or callback hooks. |
| [0005](docs/adr/0005-run-copilot-cli-agents-from-the-harness-root-with-harness-and-workspace-isolation.md) | Run Copilot CLI agents from the harness root with harness-and-workspace isolation | Copilot CLI agent cwd, agent execution root, harness root, harness isolation, workspace isolation, .github skills, harness docs, target worktree, single-repo harness, multi-repo harness | Launch Copilot CLI from the harness root so harness `.github` customizations and docs remain in context; isolate the harness and relevant workspace repositories/worktrees rather than making a target worktree the execution root. |

## Crosscutting Concepts

This section describes crosscutting concepts (practices, patterns, regulations, recurring approaches). They preserve architectural consistency.

| Concept | Trigger condition | Default |
|---------|-------------------|---------|

| **[Ralph Wiggum Loop](docs/concepts/str-ralph-wiggum-loop.md)** | autonomous coding loop, repeated agent sessions, fresh context window, context rot, external task state, shared task list or PRD, binary completion criteria, orchestration strategy, simple loop, planner or reviewer coordination | Preserve fresh sessions, external state, bounded work, and binary completion; use the Simple Loop option unless additional coordination is required. |
| **[Headless AI Agent](docs/concepts/str-headless-ai-agent.md)** | headless agent, non-interactive coding agent, programmatic agent invocation, CLI agent, worktree agent, isolated agent process, agent subprocess, timeout or cancellation, machine-readable completion, Shipyard agent execution | Invoke coding agents as bounded non-interactive processes against an explicit repository/worktree, with durable state external to the session and machine-observable completion. |

| **[Lifecycle Hooks](docs/concepts/str-lifecycle-hooks.md)** | hook, hook point, worktree-ready, pre-agent setup, setup command before agent, hook timeout, hook failure, fail fast, cancel in-flight hooks, post-agent hook, host command in worktree, copy .env, install dependencies, run lifecycle | Declare hooks as shell commands at the `worktree-ready` Hook point; the runtime runs them sequentially on the host before the agent and fails the run on a non-zero exit or timeout. |
