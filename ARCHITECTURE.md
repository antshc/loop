# Loop Overview

Loop is a Python library, installed with `pip` from this repository, for composing autonomous agent Workflows on Git worktrees. It ships no command and no built-in Workflows: the user writes each Workflow as a plain script on the public `loop` API and runs it through their own shell alias. Ralph, the orchestrator, drives the autonomous development loop; Crew agents (Codey, Chorey, Testy) do the work on worktrees from Tickets.

## Goal

Build a headless AI development environment that orchestrates coding agents across Git repositories, manages isolated single-repository and multi-repository harnesses, and supports iterative autonomous development workflows with minimal human intervention.

## Codebase Structure

| Location | Contents |
|----------|----------|
| `src/loop/` | The `loop` library package: public top-level API, contracts, and shipped implementations (worktree runner and run lifecycle, agent client, git and GitHub clients, stores). |
| `src/loop/testing/` | Test doubles for every process boundary (`gh`, `git`, the Copilot CLI, the agent client). |
| `workflows/` | The example `dev` Workflow (`dev/`, a package runnable with `python -m workflows.dev`) and its prompt template (`dev/prompts/dev.md`); the example `plan_implement` Workflow (`plan_implement.py`, a single module runnable with `python -m workflows.plan_implement`); not part of the `loop` package. |
| `tests/` | The test suite: `tests/unit/` (unit group, including Workflow tests against fakes), `tests/integration/` (integration group, selectable independently), `tests/live/` (opt-in group against the real Copilot CLI, selected with `pytest -m live`), `tests/workflow_harness.py` (shared Workflow harness and builders), and import-linter architecture checks. |
| `archive/` | Retired prototypes kept as a parts source only; excluded from search and navigation, never edited or imported. |
| `docs/` | ADRs (`adr/`), Crosscutting Concepts (`concepts/`), and research notes. |
