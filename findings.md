## Loop Persisted/Emitted Format Catalogue (for issue antshc/loop#111)

### 1. On-disk files

**a. `PrState` — `<state_dir>/prs/<owner>--<repo>--<number>.json`**
`workflows/pr_babysit/infrastructure/state.py:73-98`. Fields: `version:1`, `repo:str`, `number:int`, `status: "queued"|"ignored"|"running"|"blocked"|"completed"|"interrupted"`, `items: {id: {status:"pending"|"handled"|"superseded", ...}}`, `retries: dict`, `copilot: dict`, `batch: dict|null`. Written via `write_json` (`state.py:28-42`): UTF‑8, `json.dump(..., indent=2, sort_keys=True)` + trailing `"\n"`, via `NamedTemporaryFile` + `fsync` + `os.replace` (atomic durable write). Example round-trip in `workflows/pr_babysit/tests/infrastructure/test_state.py:11-17` (`{"version": 1, "value": "before"}`). **Persisted across runs — compatibility matters.** Golden fixture: a `prs/owner--repo--42.json` with one pending item, one retry, verified byte-for-byte (key order, 2-space indent, trailing newline).

**b. `Registry` — `<state_dir>/scheduler.json`**
`state.py:101-127`. Fields: `version:1`, `initialized:bool`, `prs: {"owner/repo#N": {repo, number, url}}`, `author:str`, `repositories: list[str]` (sorted). Same atomic `write_json`. **Persisted; compatibility matters** (identity/baseline check at `state.py:111-112` rejects mismatched author/repositories). Golden fixture: scheduler.json with 2 enrolled PRs.

**c. `worker.lock`** — `process_lock` (`state.py:46-70`) uses `fcntl.flock`/`msvcrt.locking` on an `a+b` file; no content format, pure OS advisory lock. **Ephemeral/process-local; a Bun port needs an equivalent lock primitive, not a byte format.**

**d. `settings.json` (pr_babysit config)** — read-only input, not emitted by Loop, but its schema must be reproduced for config parity: `repositories:[{name,path,build:[...],test:[...]}]`, `state_dir`, `author`, `interval`, `concurrency`, `retries`, `copilot_review`, `otel_endpoint`, `timeout` (`workflows/pr_babysit/settings.py:34-59`, example at `workflows/pr_babysit/settings.example.json`). **User-authored input; compatibility matters for ingestion.**

**e. Session store** — `src/loop/sessions/store.py:14-24` (`MemorySessionStore`) is **process-local, never persisted to disk**. No file format to replicate; only the `SessionName`/`NativeHandle` value objects (`src/loop/sessions/values.py:31-52`) matter — `SessionName.new()` is `f"loop-{uuid4().hex}"` (`values.py:42-43`). **Ephemeral — no disk fixture needed**, but the *value shapes* must match for cross-CLI session id derivation (see §2).

**f. `FileExecutionStore` — `<directory>/dev-execution-log-<UTC YYYY-MM-DD>.json`**
`workflows/dev/journal.py:20-90`. A JSON array of records: `owner, repo, type:"spec", task_id, title, task(key), count:int, last_run` (strftime `"%Y-%m-%dT%H:%M:%SZ"`), `last_items:[int,...]`. Written with `json.dumps(records, separators=(",", ":"))` (compact, no sort_keys, no indent) — **different encoding style from PrState**, so an exact byte fixture matters. **Persisted across daily runs (failure-count gate); compatibility matters.** Golden fixture: one day's log with 2 records, one reset.

### 2. Copilot/Codex session logs & CLI stdout JSON events

**Copilot session log** — read from `~/.copilot/session-state/<uuid5(session_id)>/events.jsonl` (`src/loop/clis/copilot_log.py:19-21,44-49`). Session id is deterministic: `uuid5(fixed_namespace="6f1d2c3a-...", SessionName.value)` (`copilot_log.py:14-26`). JSONL events have `type`, `data`, `timestamp`; `read_turn` slices from the last `session.start`/`session.resume` to EOF (`copilot_log.py:52-67,74-76`), summing `session.usage_record` events' `data.usage` (fields `inputTokens, outputTokens, reasoningTokens, cacheReadTokens, cacheWriteTokens, initiator, cost, copilotUsage.totalNanoAiu, copilotUsage.tokenDetails[{tokenType,tokenCount,costPerBatch,batchSize}]`, `copilot_log.py:79-103`), and pairing `tool.execution_start`/`tool.execution_complete` by `data.toolCallId` (`copilot_log.py:106-125`). Example event shape from the test helper: `{"type": kind, "data": {...}, "timestamp": "2026-10-23T13:00:00Z"}` (`tests/unit/test_observe.py:43-50`). **Read-only external format, not Loop-authored, but compatibility is mandatory** since a TS port must parse the real Copilot CLI's on-disk log exactly (including the pre-1.0.95 cumulative-totals edge case, `copilot_log.py:56-57`, and the 2-vs-3/6-digit fractional-second timestamp quirk, `copilot_log.py:128-131`). Golden fixture: a minimal `events.jsonl` with `session.start`, two `session.usage_record`s (one `initiator:"user"`, one not), one tool pair, one `assistant.message`.

**CLI stdout JSON events (Loop's own wire format)** — `src/loop/clis/transport.py`. `CopilotJson` (`--output-format json`, `transport.py:44-70`): lines are `{"type":"assistant.message_delta","data":{"deltaContent":...}}` and `{"type":"result","sessionId":...,"exitCode":...}`; `encode()` mirrors this exactly for dry-run round-trips. `CodexJson` (`--json`, `transport.py:73-97`): `{"type":"thread.started","thread_id":...}` and `{"type":"item.completed","item":{"type":"agent_message","text":...}}`. **Compatibility matters in both directions**: decode must match the real CLIs' stdout; encode must match what dry-run fixtures/tests expect byte-for-byte. Golden fixture: one decode+encode round trip per transport, taken straight from `transport.py:65` and `:92`.

### 3. JSON log record shape (`src/loop/log.py`)

`configure_logging` (`log.py:14-52`) attaches `python-json-logger`'s `JsonFormatter()` **with no custom format string** only to a `logging.FileHandler`, gated on `level <= DEBUG` and `log_file is not None` (default path `Path("loop.log")`, `log.py:10,28-29`). Empirically (verified by running the library), default `JsonFormatter()` emits exactly `{"message": "<formatted msg>"}` plus any `extra=` kwargs merged in as top-level keys, e.g. `logger.info("hello %s", "world", extra={"foo":"bar"})` → `{"message": "hello world", "foo": "bar"}`. No timestamp, level, or logger name fields are included by default (they're only in the plain-text console handler format string `"%(asctime)s %(levelname)s %(name)s: %(message)s"`, `log.py:11`). Encoding: UTF‑8 file, one JSON object per line (standard logging newline termination). **Persisted artifact (loop.log) but low-value for cross-tool consumption** unless something parses it; still, exact key set (`message` + extras, no extra implicit fields) must be reproduced for parity. Golden fixture: one DEBUG call with `extra={"cli":"copilot","exit_code":0}` → expected single JSON line.

### 4. OTel spans/attributes (`src/loop/observe/otel.py`)

Scope name `"loop"` (`otel.py:25`), default service name `"loop"` (`otel.py:26`). Spans:
- `invoke_agent {agent-or-cli}` (`otel.py:60-71`): attributes `gen_ai.operation.name="invoke_agent"`, `gen_ai.provider.name` (mapped via `_PROVIDERS={"copilot":"github.copilot","codex":"openai"}`, `otel.py:27`), `gen_ai.conversation.id`, `loop.agent.cwd`, optionally `gen_ai.agent.name`, `gen_ai.request.model`, `loop.agent.thinking`, `loop.agent.native_session_id`, `loop.agent.exit_code`, plus usage attributes (`_usage_attributes`, `otel.py:184-199`: `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, nine `loop.usage.*` fields, dynamic `loop.usage.{kind}_aiu`). Error status set via `Status(StatusCode.ERROR, record.error or f"exit code {record.exit_code}")` (`otel.py:68`).
- `execute_tool {name}` child spans (`otel.py:134-150`): `gen_ai.operation.name="execute_tool"`, `gen_ai.tool.name`, `gen_ai.tool.call.id`, `loop.tool.ok`; with `capture_content`, also `gen_ai.tool.call.arguments`/`result` (JSON-stringified).
- `loop.worktree` spans (`otel.py:72-87`) with `loop.worktree.path`, optional `loop.worktree.retained=true`.
- Metrics (`otel.py:152-180`): histograms `gen_ai.client.token.usage` (unit `{token}`), `gen_ai.client.operation.duration` (unit `s`); counters `loop.agent.aiu` (unit `{AIU}`), `loop.agent.premium_requests` (unit `{request}`); shared attrs `gen_ai.operation.name`, `gen_ai.provider.name`, optional `gen_ai.request.model`, `error.type="agent_failed"` on failure.
- Resource attributes: `service.name` (+ `service.instance.id=service.name` when `resource_per_agent=True`, `otel.py:216-225`).

**Follows GenAI semantic-conventions plus `loop.*` extensions — compatibility matters** for any dashboard/backend consuming these (e.g., Aspire). Golden fixture: one `AgentRunRecord` → expected span name, full attribute dict, and both histogram/counter data points.

### 5. Agent CLI hook contract

**Shim** (`src/loop/hooks/shim.py:22-33`) normalises Copilot (camelCase) vs Codex (snake_case) hook payloads into one JSON shape: `{point, cli, handle, cwd, resumed(bool from source=="resume"), reason, tool, session}`. It spawns the user's hook command with env `LOOP_SESSION`, `LOOP_CLI`, `LOOP_HOOK_POINT` merged over `os.environ` (`shim.py:51`), piping the normalised payload as JSON+`\n` on stdin, discarding stdout, always exiting 0 (fail-open, `shim.py:58-60`). **Compatibility matters**: the normalised JSON shape and the three `LOOP_*` env var names are the public contract a TS port's own hook-invoking commands depend on. Golden fixture: one Copilot-shaped and one Codex-shaped raw payload → identical normalised output.

**Hook config files per CLI**: Copilot writes `.github/hooks/loop-<sha1(session_name)[:8]>.json` with `{"version":1, "hooks": {<eventName>: [{"type":"command","bash":<shim_command>,"timeoutSec":...}]}}` (`src/loop/clis/copilot_cli.py:39-52`); also adds the file to `.git/info/exclude` and sets env `GITHUB_COPILOT_PROMPT_MODE_REPO_HOOKS=true`. Codex instead passes `-c hooks.<Event>=[...]` CLI args plus `--dangerously-bypass-hook-trust` (`codex_cli.py:40-54`) — **no file is written for Codex**, only process args.

**`shim_command` embeds `sys.executable`** (`src/loop/hooks/agent_cli.py:105-108`): `[sys.executable, str(_SHIM), "--cli", cli, "--point", point, "--session", name, "--", hook.command]`. This Python interpreter absolute path is baked into the Copilot hook JSON file written to the worktree — **yes, a persisted artifact does embed the interpreter path**, but it is strictly ephemeral: `ProcessCliRunner._hook_files` (`src/loop/clis/runner.py:50-64`) writes it before the subprocess call and `finally: path.unlink(missing_ok=True)` removes it immediately after, every run. **Not cross-run persisted — a Bun port only needs to replicate the JSON shape/content with its own executable path, not match Python's path.** Golden fixture: one hook config file's exact JSON (sans the interpreter path, which should be treated as an environment-specific placeholder) plus the git-exclude line `.github/hooks/loop-*.json`.

### 6. Entry-point CLI flags

- **`workflows.dev`** (`workflows/dev/run.py:42-67`, prog `"dev"`): `--log-dir PATH`, `--log-level`, `--visualize`, `--spec INT`, `--no-otel`, `--otlp-endpoint URL`, `--fake SEAM` (repeatable, choices=`SEAMS`), `--dry` (implies all fakes + default OTLP endpoint `DRY_OTLP_ENDPOINT`), `--fake-speed FLOAT` (default 1.0), `--no-rework`.
- **`workflows.pr_babysit`** (`workflows/pr_babysit/__main__.py:17-21`, no explicit prog): `--config PATH` (required), `--pr "https://github.com/owner/repo/pull/123"`, `--include-existing`, `--retry`.
- **`plan_implement`** (not a package — a standalone script `workflows/plan_implement.py:82-93`, prog `"plan_implement"`): positional `task` only (model/effort are keyword args to `main()`, not flags).

**Compatibility matters for all three** as the user-facing CLI surface a TS/Bun port's own argument parser must reproduce flag names, defaults, and `--dry`/`--fake` interaction logic (`run.py:67-71`). Golden fixture: `--help` text or a parsed-args snapshot per entry point, plus the `--dry → --fake=all seams, otlp-endpoint=DRY_OTLP_ENDPOINT` and `--fake git without --fake agent → parser.error` validation cases.
